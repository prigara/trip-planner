1. Prerequisites

ToolVersionNotes
Node.js 20.19+ or 22.12+ Required by Vite 8. Check with node -v.
npm Bundled with Node The repo ships a package-lock.json, so npm is the expected package manager.
Git Any recent version To clone the repository.
Browser Any modern browser Must allow localStorage (data is saved there).
No backend, database, API keys, or environment variables are needed — the app runs entirely in the browser.

2. Quick start

  1. Clone the repository 
    git clone <repository-url> trip-planner
cd trip-planner
  2. Install dependencies 
    npm install
    For a clean, reproducible install that strictly follows the lockfile (e.g. in CI), use npm ci instead.
  3. Start the dev server 
    npm run dev
  4. Open the app
    Visit the URL Vite prints — by default http://localhost:5173. Edits to files in src/ hot-reload automatically.
On first run the app seeds a sample Paris trip so you can try drag-and-drop right away.

4. Building for production

npm run build
npm run preview

The output in dist/ is a fully static site (HTML, JS, CSS, assets). Deploy it to any static host — GitHub Pages, Netlify, Vercel, S3, nginx, etc. No server-side runtime is required.

If you host the app under a sub-path (e.g. https://example.com/trip-planner/), set base: '/trip-planner/' in vite.config.ts before building, otherwise asset URLs will resolve against the domain root.

5. Data & storage

  • All trips are stored in the browser's localStorage under the key trip-planner-state-v2.
  • Data is per-browser and per-origin: localhost:5173 (dev) and localhost:4173 (preview) keep separate data.
  • Older data saved under trip-planner-state-v1 is migrated automatically into a single trip on load.
  • If the stored state is malformed, the app discards it and falls back to the seeded sample trip.

Resetting to a clean state

Open the browser DevTools console on the app's page and run:

localStorage.removeItem('trip-planner-state-v2')
localStorage.removeItem('trip-planner-state-v1')
location.reload()

6. Project structure

trip-planner/
├── index.html           # Vite entry HTML
├── public/              # Static assets copied as-is (favicon, icons)
├── src/
│   ├── main.tsx         # React root mount
│   ├── App.tsx          # The whole app: state, persistence, UI, drag & drop
│   ├── App.css          # Component styles
│   ├── index.css        # Global styles
│   └── assets/          # Images imported from code
├── vite.config.ts       # Vite + React plugin config
├── tsconfig*.json       # TypeScript project configs
└── eslint.config.js     # ESLint flat config

Stack: React 19 + TypeScript 6, built with Vite 8. There are no runtime dependencies beyond react and react-dom — no router or state library.

7. Troubleshooting

Vite fails to start with a Node version error

Upgrade Node to 20.19+ or 22.12+ (e.g. via nvm install 22 && nvm use 22), then reinstall:

rm -rf node_modules
npm install

Port 5173 is already in use

Vite will pick the next free port automatically and print it. To force a specific port:

npm run dev -- --port 3000

Accessing the dev server from another device / container

Expose it on all network interfaces:

npm run dev -- --host

My trips disappeared

Data lives in localStorage, so it is lost when you clear site data, use a private window, switch browsers, or open the app on a different port/origin.

npm run build fails with type errors

The build runs tsc -b first, with strict checks such as noUnusedLocals and noUnusedParameters. Fix the reported errors — the dev server does not type-check, so these can slip through during development.
